# LicitatieRO MVP Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development.
**Goal:** Ship the approved working real-estate MVP and reviewable GitHub delivery.
**Architecture:** Next.js server-only authentication and user-scoped Supabase RPCs. PostgreSQL is authoritative; browser cannot bypass auction or privacy rules.
**Tech Stack:** Node24, Next16, React19, TypeScript, Supabase, Vitest, Playwright, GitHub Actions.
**Spec:** ../specs/2026-11-13-licitatiero-design.md
## Global Constraints
- Never expose confidential bids, exact addresses or documents through public APIs.
- One auction and one active reservation per physical property.
- Financial flows are simulation only; no service-role credentials for ordinary user requests.
- Explicit RO/EN and EUR total/month units; source-controlled SQL migrations.
- €10k budget, €3k protected reserve; no account passwords/tokens in source or chat.
## Review Focus
- Concurrent changes on linked listings must serialize at property level.
- Late/idempotent requests must not create contradictory bids or reservations.
- Anonymous, unrelated and invited users have different visibility.
- Signed tenancy may enable sale; rental reservation differs from security deposit.
- Deployment must use an exact tested commit and isolated staging/production credentials.
